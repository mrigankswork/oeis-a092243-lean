# OEIS A092243, conjecture 1: a kernel-checked Lean 4 proof

**Statement** ([formal-conjectures](https://github.com/google-deepmind/formal-conjectures) `FormalConjectures/OEIS/92243.lean`,
theorem `OeisA92243.conjecture1`, tagged `research open` at commit `9097e2f`):

```lean
theorem conjecture1 : ∃ n > 250000, a n > 0
```

`a n` is the prime-gap "tug of war" score of [OEIS A092243](https://oeis.org/A092243). It starts at 0. At stage k ≥ 2 it
goes up by 1 if the k-th prime gap is larger than the previous gap, down by 1 if it is smaller, and stays the same if they are
equal. The OEIS entry asks: *"Is s > 0 for some n > 250000?"* (up to n = 250000 the score is "overwhelmingly negative").

**Answer: yes.** `a 261150 = 1`; this is the first n > 250000 with a positive score (`a 261149 = 0`).

This version of the proof uses **no `native_decide`**: every computation is checked by Lean's kernel, and the proof depends
only on the standard axioms `propext`, `Classical.choice`, `Quot.sound`.

## What is (and is not) new
- The numerical fact is **not new**. N. J. A. Sloane's table linked from the OEIS entry,
  [a092243_1.txt](https://oeis.org/A092243/a092243_1.txt) (n = 1..965562), already shows a(261150) = 1.
- What this repository adds is a **formal proof** of the formal-conjectures statement, which was still tagged
  `research open`.

with its own cross-check against a plain sieve).

## How the proof works
1. **Certificate.** Each block `[lo, lo + len)` is sieved by the kernel with the test `gcd(n, Q) = 1`, where `Q` is a product
   of small primes, and the score `step` is folded over the numbers that pass. Each block is its own theorem, and the
   theorems are chained with `runChecked_cons_of`. Result: `certs_ok : runChecked (2, 3, 0, 2) certs = some (3666539, 3666581, 1, 261151)`.
2. **The gcd test is a primality test** (`isP_iff`), when every prime `q` with `q² < hi` is one of the sieving primes.
   Bootstrap: the primes below 48 are listed and checked directly. That makes the 14 blocks below 2209 sound. The kernel
   checks that they find exactly the primes in `sp`, so every prime below 2209 is in `sp`, which makes the other 367 blocks sound.
3. **Tiling.** The blocks are consecutive from 4 to 3666582, so the numbers kept are exactly the primes in `[4, 3666582)`, in order.
4. **Fold = upstream sum.** The i-th prime below N is `Nat.nth Nat.Prime i` (via Mathlib's `Nat.nth_count`). Folding `step`
   over `p₂, …, p_m` from `(p₀, p₁, 0, 2)` gives `(p_(m−1), p_m, Σ_{k=2}^{m} sign(g_k − g_(k−1)), m + 1)`. The certificate's
   count 261151 fixes m = 261150, so `partialScore 261150 = 1`. Here `partialScore` is the sum in upstream's `a`, with `primeGap` unfolded.
5. `Solution.lean`: `unfold a`, drop the `n ≤ 1` branch, `exact partialScore_261150`; the witness is n = 261150.

## Statement fidelity
- **Same toolchain (v4.35.0-rc2).** formal-conjectures@9097e2f was built on Lean/Mathlib v4.35.0-rc2. `92243.lean`,
  `FormalConjecturesUtil` and every support file were left unchanged. One exception: the `FormalConjecturesForMathlib.lean`
  import list had to leave out 25 unrelated modules that do not build on v4.35.0-rc2.
  - The elaborated `primeGap`, `a` and the type of `conjecture1` were dumped as raw `Expr`s in that environment, in
    `Challenge.lean` and in `Solution.lean`. All three dumps are byte-identical.
  - The upstream `conjecture1` statement was also proved in an environment importing that upstream module plus
    `OeisA92243.Bridge`, with its type checked equal (`Expr ==`) to upstream's.
- **Upstream's own toolchain (v4.33.1).** formal-conjectures was built at 9097e2f with its full support library. There,
  `primeGap` and `a` elaborate to the same types and values. The only difference is `primeGap`'s reducibility-height hint,
  which is a kernel unfolding heuristic with no logical content.

## Earlier version
The first proof (v0.1) evaluated the computation with `native_decide`, which trusts the Lean compiler. It is at tag
[`v0.1`](https://github.com/mrigankswork/oeis-a092243-lean/tree/v0.1). It builds against formal-conjectures@9097e2f on Lean 4.33.1 (see `verify.sh` there).

## Building
Needs elan. Run `./verify.sh`, which does `lake exe cache get` (prebuilt Mathlib), `lake build`, and prints the axioms. A clean
build takes about 4–5 minutes and peaks at about 3.5 GB of memory. Each certificate block is a separate theorem on purpose:
one `decide +kernel` theorem covering 40 blocks needs about 10 GB.

Use the pinned toolchain (`lean-toolchain`: v4.35.0-rc2). The proof has not been built on other Lean versions. A trial on
v4.33.1 needed more than 4 GB for a single certificate file and was stopped.

Independent numerical checks, exact integers: `python3 checks/check1.py 270000` (Python sieve) and
`cc -O2 -o check2 checks/check2.c && ./check2` (C sieve) both give a(261149) = 0 and a(261150) = 1, in agreement with Sloane's table.
